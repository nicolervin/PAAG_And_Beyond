## Purpose

The Quality page maintains the approved project-wide repository of reusable Quality requirements and manual PFMEA control options, plus scenario-specific Process FMEA and Manufacturing Control Plan working-draft workflows. Contributors deliberately publish repository updates to linked Process at a Glance requirements and explicitly select applicable published assignments or manual options as Cause-level PFMEA Prevention and Detection controls. Classified PFMEA entries and their explicitly selected published Quality controls supply the MCP body-table projection.

## Connections

Repository definitions connect to scenario-specific Process at a Glance steps through `quality_requirement_assignments` and `work_elements.id`. PFMEA entries connect to the same stable Process step without changing upstream planning. Their Cause-level controls retain either the applicable published assignment identity or a project-wide manual-option identity, plus the acknowledged source version and collaborator-selected order. Nothing is auto-classified. Fishbone context remains inherited through the Process step rather than receiving a new direct relationship.

## Scope

Quality requirement definitions and manual Prevention/Detection option catalogs are project-wide. Process-step assignments, PFMEA records, PFMEA control selections, and MCP working-draft items are scenario-specific, while a repository push can update assignments in more than one scenario within the selected project. The mixed-scope Quality page therefore displays the locked **Scenario-aware** boundary indicator; its PFMEA and Control Plan tabs always use the active scenario.

## Storage

`quality_requirements`, `quality_requirement_assignments`, and `quality_requirement_torque_details` retain their documented roles. PFMEA storage includes entries, Effects, Causes, RPN rows, Actions, two project-wide manual-option catalogs, and two scenario-specific structured selection tables. `pfmea_entries.class_code` stores the approved short code and `legacy_class_code` retains retired Critical Quality evidence. The idempotent migration maps Safety/Product Safety to `S` and moves Critical Quality to legacy-plus-blank. The existing flat editor, structured control clipboard behavior, duplication, RPN, source review, and explicit repository publication remain unchanged.

`control_plan_items` stores MCP-owned fields, nullable collaborator-curated **Pr. Nº**, exclusion, source acknowledgement/review state, and source identity/snapshots. The number is synchronized across every characteristic line for one hidden Process operation, displayed only on its first currently visible line, and used only to prefix characteristic numbers; it never replaces the Process relationship or characteristic ordering. The read-only **Station / Pitch** column separately repeats the current `work_elements.station` value on every characteristic line; a mismatch with the PFMEA Pitch snapshot raises the existing source-review flag without persisting the live Pitch. New operations receive no-write suggestions until **Save & Refresh**, duplicate numbers across different operations require explicit save confirmation, and an editor-attributed one-time migration preserves the former Process-Seq-derived display. The active table is a live scenario-specific projection: one line per classified PFMEA/applicable published Quality-definition combination, deduplicated when the same assignment is selected in both PFMEA control lists, with one incomplete PFMEA-only fallback when no Quality control qualifies. Published Quality snapshots drive characteristic/specification display; Torque Type appends current Torque tool context. PFMEA controls and Actions appear as read-only evidence and never automatically populate Control method or Decision rule. Confirmed exclusion preserves content, Quality unlink preserves an orphan for explicit compatible relinking, PFMEA deletion removes dependent drafts, and scenario cloning remaps identities while retaining curated numbers. Issued status, document headers, approvals, Word export, and the deferred Process Flow Map remain unimplemented.

The Control Plan editor reuses `characteristic_placement` under the visible label **Characteristic type**; `Product / Part` is displayed as **Product** without changing stored values. Optional positive whole-number `characteristic_suffix` overrides are appended as label segments, so automatic numbering continues from `.9` to `.10`, and a Process number of `97.5` can produce `97.5.1`. Blank suffixes use the lowest available positive integer while reserving manual values, and suffixes never change `sequence` or source identity. Lines are grouped by hidden `work_elements.id`; repeated Process number and Operation cells, plus identical repeated Machine / fixture values, are blanked only in rendered/exported copies because Streamlit does not provide merged cells. Not assigned characteristic types remain visible and flagged.

## Applicable standards

Follow the complete Shared Editable-Table Implementation Checklist in `DESIGN_SYSTEM.md`, including filtering, direct entry where the row grain permits it, stable hidden IDs, native row selection, relationship-safe confirmed deletion/exclusion, filtered Excel export, **Undo**, and the footer **Save & Refresh** action. Every persisted save, bulk edit, deletion, exclusion, restore, relink, source review, and push must use `record_audit_event()` with Editor attribution, affected rows, and the store timestamp when supplied. Keep one **History** expander at the bottom of the page with Requirements, PFMEA, and Control Plan history tabs. Use canonical terminology and the traditional AIAG PFMEA/MCP field labels documented in `PFMEA_CONTROL_PLAN.md`.
